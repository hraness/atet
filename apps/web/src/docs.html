TutorialLearning-oriented

Start with the smallest complete path.

Atet is a TypeScript SDK, Bun CLI, complete local media host, and macOS desktop shell built on the same checked contracts. The first tutorial uses diagrams because it reaches an editable source and visible outputs without credentials, native capture, or a model call.

Use Atet when

  • You want source and provenance to survive the render.
  • An agent and a person need to inspect the same artifact.
  • Variants should branch from one exact project instead of copied files.
  • Local work must remain bounded and explicit.

TutorialAbout 10 minutes

Build your first checked diagram.

You will install Atet, create one source file, validate it, and render editable and fixed derivatives. Work in an empty directory so every new file is obvious.

  1. 1

    Install the CLI and inspect the host

    The public package is distributed from an immutable GitHub Release, not npm.

    TerminalInstall + doctor
    bun add --global github:hraness/atet#v2.0.0
atet doctor

    Checkpoint: atet doctor reports the local runtime and any optional capabilities. Diagram authoring does not need a Gateway credential.

  2. 2

    Create the source

    Ask Atet for a valid starter, then replace it with a small source-to-result graph.

    TerminalCreate a starter
    mkdir -p diagrams
atet diagram init diagrams/journey.diagram.json
    diagrams/journey.diagram.jsonChecked source
    {
  "$schema": "https://raw.githubusercontent.com/hraness/atet/v2.0.0/schema/diagram.schema.json",
  "version": 1,
  "name": "journey",
  "canvas": { "width": 960, "height": 540 },
  "layout": {
    "type": "stack",
    "direction": "horizontal",
    "gap": 160,
    "align": "center"
  },
  "shapes": [
    { "id": "source", "type": "rect", "width": 220, "height": 140, "label": "Source" },
    { "id": "result", "type": "rect", "width": 220, "height": 140, "label": "Result" }
  ],
  "edges": [
    { "id": "source-result", "from": "source", "to": "result" }
  ]
}
  3. 3

    Check before you render

    --strict turns every lint finding into a failed check. This is the useful mode for automation.

    TerminalValidate + render
    atet diagram check diagrams/journey.diagram.json --strict
atet diagram render diagrams/journey.diagram.json

    You now have one source and five same-stem outputs:

    journey.diagram.json
journey.tldr
journey.light.svg
journey.dark.svg
journey.light.png
journey.dark.png
  4. 4

    Choose your next move

    Open journey.tldr for editable interchange, place the SVG in a responsive interface, or use the PNG for a fixed delivery. Keep the JSON source authoritative and regenerate the derivatives after every meaningful edit.

How-to guidesGoal-oriented

Solve the task in front of you.

These guides assume you already know the result you want. Each one gives the shortest safe path and calls out the boundary that matters.

Image guide

Generate an image through Vercel AI Gateway.

Atet calls the pinned Gateway origin directly from your local process. It reads AI_GATEWAY_API_KEY first, then VERCEL_OIDC_TOKEN, and does not store or print either value.

TerminalExplicit API key
export AI_GATEWAY_API_KEY='replace-me'
atet image generate 'one cobalt circle on white' \
  --model google/gemini-3.1-flash-image-preview \
  --output artifacts/circle.webp \
  --json

For linked Vercel access, inject a short-lived token for one command instead of creating a project dotenv file:

TerminalLinked Vercel project
vercel link
vercel env run -- atet image generate \
  'a restrained chapter card on transparent black' \
  --output artifacts/chapter.webp \
  --json
Cloud boundary

The prompt and any supplied media go to Vercel AI Gateway and the selected provider. Atet sets maxRetries: 0, bounds the response, and writes the chosen output locally.

Image guide

Turn caller-owned artwork into inert SVG.

Vectorization is local, authentication-free, and network-silent after the checksum-pinned official VTracer tool is available. The result includes a receipt with source, output, binary, and fidelity evidence.

Full colorSVG
atet image vectorize mark.png \
  --output mark.svg \
  --json
DuotoneSVG
atet image vectorize mark.png \
  --output mark.duotone.svg \
  --duotone '#1f2937,#f97316' \
  --json

Custom tool location: set ATET_VTRACER_PATH to a compatible binary. Set ATET_CACHE_DIR to move the managed tool cache.

SDK guide

Use Atet from a Bun project.

Install the same immutable source into the project. Importing an SDK entrypoint does not start the CLI or inspect local state.

TerminalProject dependency
bun add github:hraness/atet#v2.0.0
vectorize.tsRoot SDK
import { vectorizeImage } from "@hraness/atet"

const result = await vectorizeImage("input.png", {
  outputPath: "artifacts/input.svg",
})

console.log({
  source: result.receipt.sourceSha256,
  output: result.receipt.svgSha256,
})

Use the root package for diagrams, image generation, vectorization, fixed semantic operations, MCP, and resource admission. Use the narrower entrypoints in the SDK reference when a boundary should be explicit.

Workflow guide

Compose checked operations into a workflow.

Portable imperative workflows are ordinary trusted Bun modules over four fixed operations. Input is parsed before work starts, step IDs are unique, and completed-step receipts survive failure.

checked-render.ts@hraness/atet/workflow
import {
  defineAtetWorkflow,
  runAtetWorkflow,
} from "@hraness/atet/workflow"

const checkedRender = defineAtetWorkflow({
  id: "checked-render",
  version: 1,
  parseInput(value: unknown) {
    if (typeof value !== "object" || value === null) throw new Error("input")
    const path = Reflect.get(value, "path")
    if (typeof path !== "string") throw new Error("path")
    return { path }
  },
  async run(workflow, input) {
    const checked = await workflow.operation(
      "check",
      "atet.diagram.check",
      input,
    )
    const rendered = await workflow.operation(
      "render",
      "atet.diagram.render",
      input,
    )
    return { checked, artifacts: rendered.artifacts }
  },
})

const run = await runAtetWorkflow(checkedRender, {
  path: "diagrams/journey.diagram.json",
})

console.log(run.output.artifacts)

For a declarative graph, use @hraness/atet/code. The graph compiles against the host's closed capability projection and rejects unsupported work before resource admission. The complete local host adds project snapshots, media analyses, edit batches, candidates, selections, and multi-format delivery workflows.

Agent guide

Give an agent a bounded Atet surface.

Choose the smallest interface that supports the task. Discovery remains separate from execution.

DiscoverRead-only
atet operations list --json
atet code search diagram --limit 4
ExecuteChecked JSON input
atet code execute atet.diagram.check \
  --input '{"path":"diagrams/journey.diagram.json"}'
MCPWorkspace boundary
atet mcp --root /absolute/path/to/workspace
Agent SkillUser scope
atet skill install \
  --target codex \
  --scope user

MCP file paths are root-relative and confined to the selected workspace. The server exposes dedicated diagram tools plus search_atet and execute_atet. It is a trusted same-user workspace boundary, not an operating-system sandbox.

For editable canvas handoff, run atet canvas open diagrams/journey.tldr. The optional installer verifies the official tldraw Offline release digest before installation.

Local media guide

Build a recording into a media project.

The complete host treats imported media and recordings as immutable sources. Analyses create evidence; edits create revisions; a render binds one exact revision to one delivery target.

  1. Capture or import. Record on Apple Silicon macOS 15+, or create a project from existing local media.
  2. Inspect and align. Bind each placement clock to project time before shared edits.
  3. Analyze. Create inactivity, music, face, scene, or speech evidence without silently editing the project.
  4. Edit. Apply cuts, speed changes, camera moves, metadata effects, captions, and overlays as a new revision.
  5. Render. Plan first, then run the exact output recipe.
TerminalOne local project path
atet record start
atet record stop
atet recordings list --json

atet projects create --from-recording <recording> --name 'First take'
atet project inspect <project> --json
atet analyze inactivity <project> --min-duration 3s --handle cut
atet project edit <project> cut 8s 11.2s
atet project render plan <project> --json
atet project render run <project> --output renders/final.mp4

More advanced surfaces include multi-angle audio alignment, offline Apple Vision face tracking, metadata-aware cursor and typed-text effects, deterministic HTML and Three.js overlays, generated image and video candidates, and immutable creative iteration matrices. Use atet operations list --json and atet workflows list --json to discover the installed host.

How-to guide

Diagnose common failures.

SymptomWhat it meansNext action
Gateway credential missingNo supported credential reached the local process.Set AI_GATEWAY_API_KEY or run the command through vercel env run --, then check atet doctor --json.
tool_platform while vectorizingThe official bounded VTracer path is unavailable on this platform.Run on macOS or Linux, or set ATET_VTRACER_PATH to a compatible verified binary.
Strict diagram check failsThe source parsed, but at least one lint finding remains.Read the reported shape or edge ID, correct the JSON source, and rerun diagram check --strict.
Operation not foundThe requested code is outside the fixed portable registry or installed host projection.Run atet code search <term> or atet operations list --json; do not guess an identifier.
Stale project or promotionThe source, plan, candidate base, or toolchain changed after the receipt was created.Re-open the current project snapshot, re-plan, and create a new revision. Do not overwrite the prior candidate.
Resource waitAnother Atet process owns an overlapping machine resource claim.Let the admitted work finish. Avoid launching a second unmanaged encoder or native build beside it.

ExplanationUnderstanding-oriented

Understand the journey, not just the command.

These sections connect Atet's design decisions. Read them when you need to decide where code belongs, what may be cached, or which boundary to trust.

One system, three execution boundaries

Portable SDK and CLI

Own diagrams, direct Gateway image generation, local vectorization, four fixed operations, declarative and imperative workflow contracts, MCP, and host-resource admission.

Complete local host

Adds recordings, immutable project storage, analyses, edit transactions, candidate iteration, durable scheduling, native helpers, overlays, and multi-format delivery.

Desktop shell

Adds macOS capture permissions and application UI. It does not create a separate workflow engine or hosted service.

The smallest sufficient boundary is usually the safest one. A diagram check should not initialize a media project; a local vectorization should not acquire network authority; a desktop permission should not leak into the portable SDK.

Source remains authoritative

Atet treats diagram JSON, scene code, workflow graphs, imported media identity, and explicit project revisions as the durable description of intent. Rendered files are replaceable results. That separation makes an artifact reproducible without pretending the artifact is the source.

1SourcesIdeas, media, text, and code with exact revisions
2Project graphTyped operations and checked relationships
3CandidatesIndependent revisions from one frozen base
4RendersExplicit preview or final recipes
5DeliveryVerified outputs bound to their identity

Local custody does not mean no network

Local custody means Atet project state and artifacts live in caller-owned storage, and the current process controls every provider call. Diagram rendering and vectorization need no network authority. Model-backed generation sends only the declared prompt and media to Gateway and the selected provider. Complete-host media uploads require an explicit --allow-cloud-upload gate.

The website is outside that execution path. It is a dependency-free static document with no analytics, API, account, authentication, billing, form, or credential input.

Cache by proof, not by filename

A reusable result needs the same meaningful inputs: source bytes, operation, options, runtime or renderer ABI, toolchain, output profile, and any provider or media evidence the operation owns. If one of those changes, the result receives a new identity. If all of them match, Atet can adopt a verified artifact without performing the expensive work again.

Candidate iteration uses the same rule. Agents can branch from one frozen project base, render independently, and compare a matrix of results. Promotion is an explicit checked operation. A concurrent editorial change preserves the candidates and rejects a stale promotion.

Bound work before it starts

Atet validates paths, source sizes, pixels, frames, arrays, responses, subprocess duration, downloads, and resource claims at the boundary that owns them. Declarative code compiles against a closed capability projection. Unsupported work fails before an executor or paid resource is admitted.

On macOS and Linux, semantic SDK, CLI, MCP, and workflow operations share crash-safe machine-global admission. CPU, local I/O, network, paid calls, native tools, and video encodes can be scheduled without parallel agents accidentally multiplying the machine load. Other platforms report a truthful process-local fallback.

How this documentation is organized

The information architecture follows Diátaxis: tutorials support learning, how-to guides support a task, reference describes the machinery, and explanation builds understanding. Those modes stay separate so you can enter at the point your work requires.
