# Direct short generated clips

These commands require current source. Check the installed `atet help direct` and [installation reference](install.md) before preparing a paid session.


Use `atet direct --help` for the installed command contract and read the [complete directing guide](https://github.com/hraness/atet/blob/main/docs/directing-video.md) for recipe examples. Start with `atet direct init recipe.json --json`, edit the stable `direct_<id>` and ordered shots, then run `atet direct plan recipe.json --json`. Planning reads live Gateway capabilities, per-second pricing, and image transport requirements without a paid generation. Use [gateway-media.md](gateway-media.md) for model discovery and process-local credentials. Gateway reads `AI_GATEWAY_API_KEY` before `VERCEL_OIDC_TOKEN`.

To use a rendered scene frame, pass the exact returned PNG path to `atet direct anchor --input <image> --json`. Set a shot's `firstFrame` to `{kind: "image", source: <complete returned reference>}`. The import is local; generation uploads only the exact references acknowledged by `--allow-cloud-upload` on that invocation. A later shot can instead set `firstFrame` to `{kind: "shot-end", shotId: "<earlier-shot-id>"}` to use its currently accepted predecessor's final decoded frame. Optional `lastFrame` needs a first frame and live model support. Retain authored prompts for every shot and inspect motion, geometry, lighting, and identity at each join. Endpoint conditioning doesn't carry a provider neural checkpoint or complete 3D world state.

For a shot whose planned `inputTransport` is `url`, configure an existing private Vercel Blob store and include `--allow-reference-hosting` alongside `--allow-cloud-upload`. H3 Max currently needs this path for image conditioning. Blob prefers `VERCEL_OIDC_TOKEN` with `BLOB_STORE_ID`, then falls back to `BLOB_READ_WRITE_TOKEN`; a Gateway API key alone cannot authorize Blob. The adapter copies at most two exact retained PNG, JPEG, or WebP images of 30 MiB each, verifies bytes and private access, then grants the model signed GET access that expires 15 minutes after issuance. It doesn't publish public URLs or retain credentials and signed URLs. GET access doesn't imply support for every provider download method. Budget for Blob storage, operations, and transfer separately from the Gateway estimate.

Create the retained budget once with `atet direct start recipe.json --budget-usd <authorized-USD> --json`. Generate one deliberate take with `atet direct generate <direct-id> --shot <shot-id> --attempt <take-id> --allow-paid-generation --json`; include the upload and hosting flags required by its references and planned transport. Inspect the actual output, then record `atet direct review <direct-id> --attempt <take-id> --decision accepted|rejected --note <review> --json`. Acceptance requires a completed video with its retained endpoint. A successful provider response can still fail local timestamp or color admission; retain those paid bytes for inspection and explicit conversion. Supported opaque 8-bit YUV with missing color tags uses the retained `untagged-8bit-yuv-assume-bt709-v1` policy: missing transfer, primaries, and matrix mean BT.709; missing range means limited range. Receipts preserve the observed tags and assumptions. Endpoint images become sRGB; conflicting tags, HDR, 10-bit formats, and video with alpha are rejected without tone mapping. Admitted RGB formats are opaque `rgb24`, `bgr24`, and `gbrp`. A rejected output and its budget reservation remain retained; another generation needs a new take ID and explicit paid invocation.

Activate changed recipes with `atet direct revise <direct-id> --recipe revised.json --json`. Inspect selection status with `atet direct inspect <direct-id> --json`. Changing a shot or selecting a different predecessor invalidates dependent takes; unrelated accepted shots stay valid. Old recipes and takes remain available. After interruption, use `atet direct resume <direct-id> --attempt <take-id> --json`. Resume reconciles local receipts and missing endpoint extraction without resubmitting a provider call. A missing journal on resume cannot release a reserved or ambiguous take; recovery can still attach a completed local receipt. Only a new reservation proven undispatched during its generation invocation can be released. The budget uses catalog estimates, not settled invoices or a provider spending cap; Gateway may make several provider attempts even with client retries disabled.

Inspect `referenceHosting` in generation results or error details. `cleanupRequired: true` needs follow-up through the included `receiptPath` and `cleanupCommand`; the receipt may be absent when unreadable. Retain `artifacts/atet/private/directing-blob/<direct-id>/<take-id>/receipt.json` after failures. Only per-entry `cleanup: "deleted"` confirms removal; `pending` or `uncertain` needs attention. Access expiry doesn't delete storage. Run `atet direct cleanup <direct-id> --attempt <take-id> --json` with credentials for the same Blob store to reconcile exact objects. Cleanup is repeatable and never regenerates video; an absent object can remain uncertain when the original upload's remote outcome is unknown. Automatic cleanup runs after completed or proven-undispatched calls and preserves references for ambiguous calls. Manual cleanup revokes future object access, so let an active generation finish if it still needs its references. Resume is local and doesn't perform Blob cleanup.

Run `atet direct assemble <direct-id> --json` only when all shots have current accepted takes. Assembly returns an ordinary V1 video project with clips in recipe order and cuts based on measured video spans. Source audio plays at unity gain within each span; leading or trailing audio outside it is trimmed so audio padding doesn't extend the video placement. Cumulative native rational video durations determine floored microsecond cuts. The version-two assembly receipt records video spans, cut positions, and audio trims under a new assembly identity while retaining older projects and take records. YUV clips use a retained sRGB RGB derivative encoded losslessly with FFmpeg `libx264rgb`, using the endpoint's color interpretation and complete copied audio. Placements apply the trims; derivative admission verifies frame timestamps, final-frame duration, geometry, and audio timing. Original media remains unchanged. This local encode is bounded to 120 seconds and 512 MiB per derivative. Keep the original, derivative, and normalization receipts, which bind source/output hashes, interpretation, and encoder version. Inspect the returned project ID, apply ordinary timeline or audio edits, and use `atet project render plan|run <project-id> --json` for delivery. Review, resume, and assembly are local and need no cloud credential. This path doesn't replace candidate footage in the V2 scene compositor. Preserve receipt and source files when reusing a project or continuing a directing session.
